# OpenJev 的数据长什么样

每行 JSONL 是一个判断问题。模型输入包括 state（状态或原文）和 question
（判断类型、完整问题、候选描述）；监督目标是按候选顺序排列的 target 向量。
id、source、source_id、group_id、split 和 provenance 用于追踪与防止数据泄漏，
不作为提示交给模型。

## 当前 v0.1 数据的真实样例

下面来自原始训练记录，只省略了较长的追踪字段：

~~~json
{
  "state": "I have been charged two times for one transaction.",
  "question": {
    "type": "noul",
    "instructions": "The customer is asking about passcode forgotten.",
    "criteria": {
      "false": "The customer is not asking about passcode forgotten.",
      "true": "The customer is asking about passcode forgotten."
    }
  },
  "target": [1.0, 0.0],
  "source": "banking77",
  "split": "train"
}
~~~

意思是：原文在说重复扣费，问题在问是否忘记密码，所以标签是假。
这个例子也说明旧版随机负例比较容易，不能代表困难的事实判断。

Choice 使用若干命名候选，target 的非零项对应正确候选。Score 使用有序
候选，例如负面／中性／正面。一个 target=[0,1,0] 的硬标签表示正确项是
第二项，不表示我们测得了“100% 的真实置信度”。概率是否可靠需要另外评测。

精确概率模拟器的一个真实例子是袋中有 11 个黄球、7 个白球、21 个红球；
目标为 [11/39,7/39,21/39]。这些软标签有数学真值，但不能替代自然语言
判断中的不确定性数据。

完整的四种记录在 ../examples/data_records_v01.json。

## 旧版训练组成

| 来源 | 训练记录数 | 作用 |
| --- | ---: | --- |
| BANKING77 | 12,168 | 意图选择与派生的真假判断；同一原文可有多个视图 |
| TweetEval sentiment | 5,389 | 三档情感评分 |
| 精确概率模拟器 | 1,794 | 概率分布诊断 |
| DeepSeek 改写 | 176 | 训练文本增强；不是人工真值 |

前面三项共 19,351 条记录、13,267 个独立来源组。改写继承父样本的分组，
因此不能把所有记录数当成独立标注原文数。

## 抽查发现的问题

- 多数候选描述只是把英文类别名中的下划线替换为空格。
- BANKING77 的单类别标签派生为宽泛语义命题时，相关类别可能造成歧义。
- 部分 TweetEval 文本有异常引号／转义字符。
- 旧合成数据中 8 条触发了联系方式样式检测；这不证明是真实个人信息，
  但不适合未经检查直接扩充公开语料。
- 教师同意原标签仍不能消除情感歧义；一个礼貌的中性请求可能被标成正面。
- 大多数语义任务只有硬标签，不能把教师自报的小数当成可靠软标签。

## v0.2 的处理

保留旧版原文件和结果，新版独立放在 data/v02，避免修改已报告实验。
首个 Qwen LoRA 试验排除全部旧合成数据，过滤联系方式样式和异常转义，
使用词面近邻候选采样，并把真假问题限定为“最佳单一意图标签”。
这个近邻启发式仍会产生简单负例；公开数据中也有上下文不足的短句，
所以筛选后的数据不等于已经获得无争议的语义真值。

本轮局部训练集为 768 条（Choice、Noul、Score 各 256），开发集与校准集
各 96 条。固定测试集有 448 条，包括旧任务回归、新来源的未见类别、
ARC-Easy、BoolQ，以及中英文规则评分。另固定 64 条用于 DeepSeek 横向参考。

所有本地模型收到相同状态、问题、候选及顺序；入选样本同时满足各模型的
输入限制，避免一个模型被截断而另一个看到全文。来源 ID、分组和测试集合
在训练模型选择前固定。具体计数见 ../reports/v02/manifest.json。
